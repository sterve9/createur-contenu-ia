01.V2.1 — Besoin Client (V2.1 — Frontend Dashboard)
Rôle du document
Ce document formalise le besoin exprimé pour la V2.1, extension frontend de la V2 STABLE.
Il s'appuie sur le §15 du document 01.V2_Besoin_Client.md qui a formellement acté que le tableau de bord personnel (mentionné aux §7 et §12 du besoin V2) était reporté à cette phase.

1. Rappel du contexte
La V2 STABLE (livrée le 10/08/2026, tag v2.0.0-stable) fournit un backend complet :

Découpage automatique de scripts V1 en scènes + plans
Génération de prompts image et animation optimisés par plan
Génération de descriptions/hashtags pour TikTok, YouTube Shorts, Instagram Reels
Clôture du dossier avec suivi d'avancement (checklist 9 étapes)
Cependant, la consultation de ces dossiers se fait aujourd'hui uniquement via requêtes SQL directes dans Supabase — inadapté au persona "side-hustler ambitieux" du projet.

2. Nouveau problème métier V2.1
Le créateur dispose d'un pipeline backend puissant mais ne peut pas l'exploiter en pratique sans compétence SQL.

Concrètement, aujourd'hui pour utiliser un dossier V2, il doit :

Ouvrir Supabase
Naviguer dans les tables v2_dossiers_production, v2_scenes, v2_plans, etc.
Écrire ou copier des requêtes SQL avec des JOINs
Copier manuellement chaque prompt/description depuis les résultats de table
Aucun retour visuel structuré, aucune sensation de "dossier prêt à consommer"
Ce processus tue la valeur du travail V2 : le persona ciblé n'utilisera jamais SQL au quotidien.

3. Persona ciblé (rappel)
Le persona reste le créateur "side-hustler ambitieux" (défini au §4 de 01.V2_Besoin_Client.md) :

Emploi principal + création vidéo le soir/week-end
3 à 8 vidéos par mois
Contrainte principale : temps disponible
Pas de compétence SQL, pas de temps pour en acquérir
Cherche une interface simple pour exploiter le pipeline V2
4. Résultat attendu de la V2.1
Le créateur souhaite disposer d'un tableau de bord web accessible via une URL simple, où il peut :

Voir la liste de ses dossiers de production avec leur statut d'un coup d'œil
Consulter le détail complet d'un dossier (scènes, plans, prompts, descriptions)
Copier facilement chaque prompt/description pour le coller dans ses outils (1 clic)
Créer un nouveau dossier depuis un formulaire (au lieu d'utiliser curl)

6. Contraintes techniques V2.1
Stack imposée
Couche	Choix
Framework	Next.js 15 (App Router, TypeScript)
UI Kit	shadcn/ui + Tailwind CSS
Base de données	Supabase existante (partagée avec V2)
Auth	Supabase Auth — Magic Link
Hébergement	Vercel (gratuit, natif Next.js)
Domaine	dashboard.sterveshop.cloud
Repo Git	Nouveau repo : createur-contenu-ia-dashboard
Justifications synthétiques
Next.js 15 : standard industriel 2026, écosystème massif, doc Supabase 1st class
shadcn/ui : composants pros gratuits, look moderne, code copy-owned
Supabase Auth Magic Link : sécurité industry standard, UX moderne, extensibilité multi-user
Vercel : natif Next.js, gratuit hobby, déploiement automatique via Git
Nouveau repo séparé : séparation propre backend/frontend, deploys Vercel isolés
7. Contraintes métier V2.1
Sécurité obligatoire : le dashboard peut déclencher des appels LLM coûteux — auth non négociable
Solo utilisateur en V2.1 mais scoping user_id prêt pour multi-user futur (V2.2+)
Pas d'impact sur le backend V2 : aucune modification des workflows n8n existants
Une seule migration DB : ajout d'une colonne user_id NOT NULL sur v2_dossiers_production (avec rétro-assignation des dossiers existants au user admin)
UX orientée "copie rapide" : le persona doit pouvoir passer d'un dossier à ses outils en < 30 secondes
8. Ce qui reste manuel dans la V2.1
La V2.1 assume de ne pas automatiser :

La génération réelle des images (reste dans Playground AI, Midjourney, SeaArt, Tensor.Art)
La génération réelle des animations (reste dans Kling AI, Pika, Hailuo, Runway)
Le montage vidéo (CapCut)
Les sous-titres, effets, validation finale
La publication sur les plateformes
Cohérent avec la V2 : ces tâches restent la valeur créative du créateur.

9. Critères d'acceptation V2.1
La V2.1 sera considérée comme satisfaisante si :

 Un utilisateur peut se connecter via magic link en < 30 secondes
 Un utilisateur voit la liste de ses dossiers de production en < 3 secondes après login
 Un utilisateur peut consulter le détail complet d'un dossier (18 plans + 3 descriptions) sans quitter la page
 Chaque prompt/description a un bouton "Copier" fonctionnel avec feedback visuel
 Un utilisateur peut créer un nouveau dossier via le formulaire, sans avoir à utiliser curl
 Le dashboard est déployé sur dashboard.sterveshop.cloud en HTTPS
 Aucun accès public possible sans authentification
 Le code est versionné dans createur-contenu-ia-dashboard avec tag v2.1.0-stable
10. Ce que la V2.1 n'est PAS
Ce n'est pas un CMS multi-utilisateurs avec gestion de rôles
Ce n'est pas un outil de génération réelle d'images/vidéos (V2.1 pilote V2, pas les outils IA externes)
Ce n'est pas un outil de montage vidéo
Ce n'est pas un outil de publication automatique multi-plateformes
Ce n'est pas une refonte de l'architecture V2 (extension pure)

12. Positionnement par rapport à la V2
La V2.1 ne remplace pas la V2.
Elle en constitue l'interface d'exploitation, dans la continuité philosophique :

La V1 apporte la matière première (script)
La V2 apporte le contexte d'exécution (prompts + descriptions)
La V2.1 apporte l'expérience utilisateur (dashboard qui rend le tout consommable)
Le backend V2 reste opérationnel et intact.
La V2.1 se greffe dessus via l'API Supabase + le webhook n8n V2.
