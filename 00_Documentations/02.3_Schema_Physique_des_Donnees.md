# 02.3 — Schéma Physique des Données

## Rôle du document

Ce document décrit la traduction physique du modèle de données métier.
Il répond aux questions :

- Comment les objets métier sont-ils stockés dans la base de données ?
- Quelles tables existent ?
- Quelles colonnes composent chaque table ?
- Quelles relations existent entre elles ?
- Quelles contraintes garantissent l'intégrité des données ?

Il sert de référence pour l'implémentation de la base **PostgreSQL** (schéma `public`).

---

## 1. Vue d'ensemble

```
campagnes ──────────────► journal_execution
    │
    ▼
contenus
    │
    ▼
analyses (contenu_id UNIQUE)
    │
    ▼
scripts (analyse_id UNIQUE, contenu_id NULLABLE)
    │
    ▼
publications  (Prévue — non implémentée)
```

Chaque table implémente un objet métier identifié dans `02.1`.

---

## 2. Table : `campagnes`

**Mission** : Tracer chaque campagne de veille, son état d'avancement et sa clôture.

| Colonne | Type | Contraintes | Origine |
|---------|------|-------------|---------|
| `id` | SERIAL | PK | Auto |
| `sujet` | TEXT | NOT NULL | C03 |
| `plateforme` | TEXT | NOT NULL | C03 |
| `langue` | TEXT | NOT NULL | C03 |
| `nb_resultats` | INTEGER | NOT NULL | C03 |
| `statut` | TEXT | NOT NULL, valeurs : `EN_COURS`, `TERMINEE`, `ERREUR` | C03, C15, E04 |
| `nb_contenus_total` | INTEGER | DEFAULT 0 | C05c |
| `nb_contenus_traites` | INTEGER | DEFAULT 0 | C15 |
| `date_creation` | TIMESTAMP WITH TIME ZONE | NOT NULL, DEFAULT NOW() | Auto |
| `date_fin` | TIMESTAMP WITH TIME ZONE | NULLABLE | C15 ou E04 |
| `execution_id` | TEXT | NOT NULL | C03 |

**DDL** :
```sql
CREATE TABLE campagnes (
  id                   SERIAL PRIMARY KEY,
  sujet                TEXT NOT NULL,
  plateforme           TEXT NOT NULL,
  langue               TEXT NOT NULL,
  nb_resultats         INTEGER NOT NULL,
  statut               TEXT NOT NULL DEFAULT 'EN_COURS',
  nb_contenus_total    INTEGER NOT NULL DEFAULT 0,
  nb_contenus_traites  INTEGER NOT NULL DEFAULT 0,
  date_creation        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  date_fin             TIMESTAMP WITH TIME ZONE,
  execution_id         TEXT NOT NULL,
  CONSTRAINT chk_campagne_statut
    CHECK (statut IN ('EN_COURS','TERMINEE','ERREUR')),
  CONSTRAINT chk_campagne_compteurs
    CHECK (nb_contenus_traites <= nb_contenus_total OR nb_contenus_total = 0)
);

CREATE INDEX idx_campagnes_execution_id ON campagnes (execution_id);
CREATE INDEX idx_campagnes_statut       ON campagnes (statut);
```

## 3. Table : `contenus`

**Mission** : Conserver tous les contenus bruts collectés, historisés et rattachés à une campagne.

*(Note architecturale : renommée depuis `prospects` pour refléter le vocabulaire métier des contenus.)*

| Colonne | Type | Contraintes | Origine |
|---------|------|-------------|---------|
| `id` | SERIAL | PK | Auto |
| `campagne_id` | INTEGER | NOT NULL, FK → `campagnes.id` | C06 |
| `contenu_source_id` | TEXT | UNIQUE, NOT NULL | C06 |
| `titre` | TEXT | NOT NULL | C06 |
| `auteur` | TEXT | | C06 |
| `description` | TEXT | | C06 |
| `date_publication` | TIMESTAMP WITH TIME ZONE | | C06 |
| `plateforme` | TEXT | NOT NULL | C06 |
| `created_at` | TIMESTAMP WITH TIME ZONE | DEFAULT NOW() | Auto |

**DDL** :
```sql
CREATE TABLE contenus (
  id                 SERIAL PRIMARY KEY,
  campagne_id        INTEGER NOT NULL REFERENCES campagnes(id) ON DELETE CASCADE,
  contenu_source_id  TEXT NOT NULL UNIQUE,
  titre              TEXT NOT NULL,
  auteur             TEXT,
  description        TEXT,
  date_publication   TIMESTAMP WITH TIME ZONE,
  plateforme         TEXT NOT NULL,
  created_at         TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_contenus_campagne_id ON contenus (campagne_id);
```

## 4. Table : `analyses`

**Mission** : Stocker l'enrichissement sémantique et l'évaluation IA d'un contenu.

| Colonne | Type | Contraintes | Origine |
|---------|------|-------------|---------|
| `id` | SERIAL | PK | Auto |
| `contenu_id` | INTEGER | NOT NULL, UNIQUE, FK → `contenus.id` | C09 |
| `resume` | TEXT | NOT NULL | C09 |
| `theme` | VARCHAR(255) | NOT NULL | C09 |
| `sentiment` | VARCHAR(50) | NOT NULL, valeurs : `Positif`, `Neutre`, `Négatif` | C09 |
| `score_qualite` | INTEGER | | C09 |
| `mots_cles` | TEXT[] | | C09 |
| `langue` | VARCHAR(10) | NOT NULL | C09 |
| `created_at` | TIMESTAMP WITH TIME ZONE | DEFAULT NOW() | Auto |

**DDL** :
```sql
CREATE TABLE analyses (
  id             SERIAL PRIMARY KEY,
  contenu_id     INTEGER NOT NULL UNIQUE REFERENCES contenus(id) ON DELETE CASCADE,
  resume         TEXT NOT NULL,
  theme          VARCHAR(255) NOT NULL,
  sentiment      VARCHAR(50) NOT NULL,
  score_qualite  INTEGER,
  mots_cles      TEXT[],
  langue         VARCHAR(10) NOT NULL,
  created_at     TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  CONSTRAINT chk_analyse_sentiment
    CHECK (sentiment IN ('Positif','Neutre','Négatif')),
  CONSTRAINT chk_analyse_score
    CHECK (score_qualite IS NULL OR (score_qualite BETWEEN 0 AND 100))
);
```

## 5. Table : `scripts`

**Mission** : Conserver le script vidéo généré par l'IA à partir d'une analyse.

| Colonne | Type | Contraintes | Origine |
|---------|------|-------------|---------|
| `id` | SERIAL | PK | Auto |
| `analyse_id` | INTEGER | NOT NULL, UNIQUE, FK → `analyses.id` | C13 |
| `contenu_id` | INTEGER | FK → `contenus.id` | C13 |
| `script` | TEXT | NOT NULL | C13 |
| `created_at` | TIMESTAMP WITH TIME ZONE | DEFAULT NOW() | Auto |

**DDL** :
```sql
CREATE TABLE scripts (
  id          SERIAL PRIMARY KEY,
  analyse_id  INTEGER NOT NULL UNIQUE REFERENCES analyses(id) ON DELETE CASCADE,
  contenu_id  INTEGER REFERENCES contenus(id) ON DELETE SET NULL,
  script      TEXT NOT NULL,
  created_at  TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_scripts_contenu_id ON scripts (contenu_id);
```

**Note** : `contenu_id` est présent comme raccourci de traçabilité pour éviter les jointures multiples. Il est écrit par C13 (mapping explicite).

## 6. Table : `journal_execution`

**Mission** : Journaliser les incidents et événements techniques rattachés à une campagne, à des fins d'audit et de diagnostic.

| Colonne | Type | Contraintes | Origine |
|---------|------|-------------|---------|
| `id` | SERIAL | PK | Auto |
| `campagne_id` | INTEGER | FK → `campagnes.id` | E03 |
| `niveau` | TEXT | NOT NULL, valeurs : `ERREUR` (extensible : `WARN`, `INFO`) | E03 |
| `etape` | TEXT | NOT NULL | E03 |
| `message` | TEXT | NOT NULL | E03 |
| `created_at` | TIMESTAMP WITH TIME ZONE | DEFAULT NOW() | Auto |

**DDL** :
```sql
CREATE TABLE journal_execution (
  id           SERIAL PRIMARY KEY,
  campagne_id  INTEGER REFERENCES campagnes(id) ON DELETE CASCADE,
  niveau       TEXT NOT NULL,
  etape        TEXT NOT NULL,
  message      TEXT NOT NULL,
  created_at   TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_journal_campagne_id ON journal_execution (campagne_id);
CREATE INDEX idx_journal_niveau      ON journal_execution (niveau);
```

**Note** : `campagne_id` est NULLABLE car en cas d'erreur très précoce (avant la création de la campagne), il pourrait ne pas être résolu par la jointure sur `execution_id`.

## 8. Relations

```
campagnes (1) ─────────► contenus (N)
    │                        │
    │                        ▼
    │                    analyses (1)
    │                        │
    │                        ▼
    │                    scripts (1) ──► publications (N)  [V2]
    │
    └────────────────► journal_execution (N)
```

- Une **campagne** contient N **contenus** et N entrées de **journal**.
- Un **contenu** appartient à une seule campagne et possède au plus une **analyse**.
- Une **analyse** possède au plus un **script**.
- Un **script** conserve un lien direct vers son contenu source (`contenu_id`) pour faciliter la traçabilité.
- Une entrée du **journal d'exécution** est rattachée à une campagne (ou orpheline en cas d'incident très précoce).

---

## 9. Contraintes d'intégrité

Le système applique les règles suivantes :

- **Cardinalité** :
  - une campagne peut contenir plusieurs contenus collectés ;
  - un contenu appartient à une seule campagne (`campagne_id` NOT NULL) ;
  - un contenu possède au plus une analyse associée (`analyses.contenu_id` UNIQUE) ;
  - une analyse possède au plus un script associé (`scripts.analyse_id` UNIQUE).

- **Unicité** :
  - `contenus.contenu_source_id` est UNIQUE — empêche les doublons lors des collectes successives (idempotence de C06) ;
  - `analyses.contenu_id` est UNIQUE — idempotence de C09 ;
  - `scripts.analyse_id` est UNIQUE — idempotence de C13.

- **Cohérence métier** :
  - `campagnes.statut` ∈ {`EN_COURS`, `TERMINEE`, `ERREUR`} (CHECK) ;
  - `analyses.sentiment` ∈ {`Positif`, `Neutre`, `Négatif`} (CHECK) ;
  - `analyses.score_qualite` ∈ [0, 100] (CHECK) ;
  - `campagnes.nb_contenus_traites` ≤ `campagnes.nb_contenus_total` (CHECK).

- **Cascade** :
  - suppression d'une campagne → suppression de ses contenus, analyses, scripts et entrées de journal.

- **Indexation** :
  - index sur `campagnes.execution_id` (utilisé par E03 et E04 pour retrouver la campagne) ;
  - index sur `campagnes.statut` (utilisé pour les requêtes de supervision) ;
  - index sur `contenus.campagne_id` (utilisé pour agrégations) ;
  - index sur `journal_execution.campagne_id` et `niveau` (audits).

---

## 10. Validation

Le schéma physique est considéré comme valide lorsque :

- toutes les tables implémentées correspondent au modèle métier (`02.1`) ;
- toutes les colonnes réellement utilisées par les workflows sont présentes ;
- toutes les relations sont matérialisées par des clés étrangères ;
- les contraintes d'unicité empêchent tout doublon ;
- les contraintes CHECK protègent l'intégrité sémantique (statuts, sentiments, scores, compteurs) ;
- les index nécessaires aux jointures critiques sont créés (notamment `execution_id`) ;
- les composants prévus mais non implémentés sont clairement identifiés.
