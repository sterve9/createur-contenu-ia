# 02.3 — Schéma Physique des Données

## Rôle du document

Ce document décrit la traduction physique du modèle de données métier.
Il répond aux questions :

- Comment les objets métier sont-ils stockés dans la base de données ?
- Quelles tables existent ?
- Quelles colonnes composent chaque table ?
- Quelles relations existent entre elles ?
- Quelles contraintes garantissent l'intégrité des données ?

Il sert de référence pour l'implémentation de la base **PostgreSQL** (schéma `public` de Supabase).

---

## 1. Vue d'ensemble

campagnes ──────────────► journal_execution
│
▼
contenus
│
▼
analyses (contenu_id UNIQUE)
│
▼
scripts (analyse_id UNIQUE, contenu_id NULLABLE)


Chaque table implémente un objet métier identifié dans `02.1`.

---

## ⚠️ Anomalies physiques connues (Héritage V1 STABLE)

Afin de préserver la stabilité de la V1 livrée sans casser l'existant, les particularités suivantes sont documentées et seront régularisées lors de la phase de conception de la V2 :
1. **Mismatch de clé `scripts.contenu_id`** : `contenus.id` est un `INTEGER` tandis que `scripts.contenu_id` est de type `BIGINT`.
2. **Mismatch de clé `journal_execution.campagne_id`** : `campagnes.id` est de type `BIGINT` tandis que `journal_execution.campagne_id` est de type `INTEGER`.
3. **Fuseau horaire du Journal d'exécution** : `journal_execution.date` est de type `TIMESTAMP WITHOUT TIME ZONE`, contrairement aux autres tables qui utilisent `TIMESTAMP WITH TIME ZONE` (`timestamptz`).

## 2. Table : `campagnes`

**Mission** : Tracer chaque campagne de veille, son état d'avancement et sa clôture.

| Colonne | Type | Contraintes | Origine | Description / Remarque |
|---------|------|-------------|---------|------------------------|
| `id` | BIGINT | PRIMARY KEY | Auto | Généré automatiquement par défaut |
| `created_at` | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | Auto | Date d'initialisation de la campagne |
| `sujet` | TEXT | NOT NULL | C03 | Critère de recherche |
| `plateforme` | TEXT | NOT NULL | C03 | Plateforme cible |
| `langue` | TEXT | NOT NULL | C03 | Langue de recherche |
| `nb_resultats` | INTEGER | NOT NULL | C03 | Nombre de contenus demandés |
| `statut` | TEXT | NOT NULL, DEFAULT 'EN_COURS' | C03, C15, E04 | `EN_COURS`, `TERMINEE`, `ERREUR` |
| `date_fin` | TIMESTAMPTZ | NULLABLE | C15, E04 | Date de statut terminal |
| `execution_id` | VARCHAR(255) | NULLABLE | C03 | ID de l'exécution n8n |
| `nb_contenus_total` | INTEGER | NOT NULL, DEFAULT 0 | C05c | Nombre de contenus collectés |
| `nb_contenus_traites`| INTEGER | NOT NULL, DEFAULT 0 | C15 | Nombre de contenus traités |

**DDL Réel Supabase** :
```sql
CREATE TABLE campagnes (
  id                   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  created_at           TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  sujet                TEXT NOT NULL,
  plateforme           TEXT NOT NULL,
  langue               TEXT NOT NULL,
  nb_resultats         INTEGER NOT NULL,
  statut               TEXT NOT NULL DEFAULT 'EN_COURS',
  date_fin             TIMESTAMP WITH TIME ZONE,
  execution_id         VARCHAR(255),
  nb_contenus_total    INTEGER NOT NULL DEFAULT 0,
  nb_contenus_traites  INTEGER NOT NULL DEFAULT 0,
  CONSTRAINT chk_campagne_statut
    CHECK (statut IN ('EN_COURS','TERMINEE','ERREUR'))
);

CREATE INDEX idx_campagnes_execution_id ON campagnes (execution_id);
CREATE INDEX idx_campagnes_statut       ON campagnes (statut);
3. Table : contenus
Mission : Conserver tous les contenus bruts collectés, historisés et rattachés à une campagne.

Colonne	Type	Contraintes	Origine	Description / Remarque
id	INTEGER	PRIMARY KEY	Auto	Généré par défaut
campagne_id	INTEGER	NULLABLE, FK → campagnes.id	C06	Campagne d'appartenance
contenu_source_id	VARCHAR(255)	UNIQUE, NOT NULL	C06	ID d'origine (ex: YouTube ID)
titre	TEXT	NOT NULL	C06	Titre collecté
auteur	VARCHAR(255)	NULLABLE	C06	Nom de l'auteur / chaîne
description	TEXT	NULLABLE	C06	Description collectée
date_publication	TIMESTAMPTZ	NULLABLE	C06	Date de publication originale
plateforme	VARCHAR(255)	NOT NULL	C06	Plateforme d'origine
created_at	TIMESTAMPTZ	NULLABLE, DEFAULT NOW()	Auto	Date d'insertion dans la base
DDL Réel Supabase :

SQL

CREATE TABLE contenus (
  id                 INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  campagne_id        INTEGER REFERENCES campagnes(id) ON DELETE CASCADE,
  contenu_source_id  VARCHAR(255) NOT NULL UNIQUE,
  titre              TEXT NOT NULL,
  auteur             VARCHAR(255),
  description        TEXT,
  date_publication   TIMESTAMP WITH TIME ZONE,
  plateforme         VARCHAR(255) NOT NULL,
  created_at         TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE INDEX idx_contenus_campagne_id ON contenus (campagne_id);
4. Table : analyses
Mission : Stocker l'enrichissement sémantique et l'évaluation IA d'un contenu.

Colonne	Type	Contraintes	Origine	Description / Remarque
id	INTEGER	PRIMARY KEY	Auto	Généré par défaut
contenu_id	INTEGER	NULLABLE, UNIQUE, FK → contenus.id	C09	Contenu analysé
resume	TEXT	NOT NULL	C09	Résumé généré par l'IA
theme	VARCHAR(255)	NOT NULL	C09	Thème principal IA
sentiment	VARCHAR(255)	NOT NULL	C09	Positif, Neutre ou Négatif
score_qualite	INTEGER	NULLABLE	C09	Évaluation sémantique [0, 100]
mots_cles	TEXT[]	NULLABLE (ARRAY)	C09	Liste de mots-clés
langue	VARCHAR(255)	NOT NULL	C09	Langue détectée par l'IA
created_at	TIMESTAMPTZ	NULLABLE, DEFAULT NOW()	Auto	Date de création de l'analyse
DDL Réel Supabase :

SQL

CREATE TABLE analyses (
  id             INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  contenu_id     INTEGER UNIQUE REFERENCES contenus(id) ON DELETE CASCADE,
  resume         TEXT NOT NULL,
  theme          VARCHAR(255) NOT NULL,
  sentiment      VARCHAR(255) NOT NULL,
  score_qualite  INTEGER,
  mots_cles      TEXT[],
  langue         VARCHAR(255) NOT NULL,
  created_at     TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  CONSTRAINT chk_analyse_sentiment
    CHECK (sentiment IN ('Positif','Neutre','Négatif')),
  CONSTRAINT chk_analyse_score
    CHECK (score_qualite IS NULL OR (score_qualite BETWEEN 0 AND 100))
);
5. Table : scripts
Mission : Conserver le script vidéo généré par l'IA à partir d'une analyse.

Colonne	Type	Contraintes	Origine	Description / Remarque
id	INTEGER	PRIMARY KEY	Auto	Généré par défaut
analyse_id	INTEGER	UNIQUE, NOT NULL, FK → analyses.id	C13	Analyse de référence
script	TEXT	NOT NULL	C13	Corps du script IA
created_at	TIMESTAMPTZ	NULLABLE, DEFAULT NOW()	Auto	Date de génération du script
contenu_id	BIGINT	NULLABLE, FK → contenus.id	C13	Clé de traçabilité directe (mismatch BIGINT vs INTEGER contenus.id)
DDL Réel Supabase :

SQL

CREATE TABLE scripts (
  id          INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  analyse_id  INTEGER NOT NULL UNIQUE REFERENCES analyses(id) ON DELETE CASCADE,
  script      TEXT NOT NULL,
  created_at  TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  contenu_id  BIGINT REFERENCES contenus(id) ON DELETE SET NULL
);

CREATE INDEX idx_scripts_contenu_id ON scripts (contenu_id);
6. Table : journal_execution
Mission : Journaliser les incidents et événements techniques rattachés à une campagne à des fins d'audit.

Colonne	Type	Contraintes	Origine	Description / Remarque
id	INTEGER	PRIMARY KEY	Auto	Généré par défaut
campagne_id	INTEGER	NULLABLE, FK → campagnes.id	E03	Campagne liée (mismatch INTEGER vs BIGINT campagnes.id)
niveau	VARCHAR(255)	NOT NULL	E03	Criticité (ex : ERREUR)
etape	VARCHAR(255)	NULLABLE	E03	Étape / nœud n8n en faute
message	TEXT	NULLABLE	E03	Descriptif de l'erreur
date	TIMESTAMP	NULLABLE, DEFAULT NOW()	Auto	Date brute de l'événement (sans fuseau horaire)
DDL Réel Supabase :

SQL

CREATE TABLE journal_execution (
  id           INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  campagne_id  INTEGER REFERENCES campagnes(id) ON DELETE CASCADE,
  niveau       VARCHAR(255) NOT NULL,
  etape        VARCHAR(255),
  message      TEXT,
  date         TIMESTAMP WITHOUT TIME ZONE DEFAULT NOW()
);

CREATE INDEX idx_journal_campagne_id ON journal_execution (campagne_id);
CREATE INDEX idx_journal_niveau      ON journal_execution (niveau);

8. Contraintes d'intégrité
Unicité :

contenus.contenu_source_id est UNIQUE (garantit l'idempotence des collectes).
analyses.contenu_id est UNIQUE (une seule analyse par contenu collecté).
scripts.analyse_id est UNIQUE (un seul script par analyse).
Cohérence métier :

campagnes.statut ∈ {EN_COURS, TERMINEE, ERREUR} (CHECK).
analyses.sentiment ∈ {Positif, Neutre, Négatif} (CHECK).
analyses.score_qualite ∈ [0, 100] (CHECK).
Cascade :

La suppression d'une campagne supprime par cascade ses contenus, analyses, scripts et entrées de journal (ON DELETE CASCADE).
La suppression d'un contenu met à null la référence directe sur le script lié (ON DELETE SET NULL).
