# 02.4 — Mapping des Données

## Rôle du document

Ce document décrit la circulation des données entre les composants du workflow et la base de données.
Il répond aux questions :

- Où une donnée est-elle créée ?
- Où est-elle enrichie ?
- Où est-elle enregistrée ?
- Où est-elle simplement transmise ?
- Quel composant est responsable de chaque donnée ?

Il constitue le référentiel officiel de propagation des données dans le système.

---

## Principe

Une donnée ne doit avoir qu'un seul propriétaire.
Un composant peut :
- **créer** une donnée ;
- **enrichir** une donnée ;
- **enregistrer** une donnée ;
- **transmettre** (propager) une donnée.

Il ne doit jamais modifier une donnée dont il n'est pas responsable.

**Exception documentée** : l'objet **Campagne** est modifié par plusieurs composants au cours de son cycle de vie (C03 → C05c → C15 → E04), mais **chaque composant n'écrit que les colonnes qui lui sont assignées** (voir tableaux ci-dessous). Cette exception est nécessaire pour matérialiser la machine à états de la campagne (compteurs, statuts, dates).

---

## Objet métier : Campagne

| Composant | Action | Colonnes concernées |
|-----------|--------|---------------------|
| **C01 — Recevoir Demande Campagne** | Réception des paramètres bruts | `sujet`, `plateforme`, `langue`, `nb_resultats` (dans le payload) |
| **C02 — Valider Paramètres** | Validation des paramètres | *(aucune écriture)* |
| **C03 — Créer Campagne** | Création de la campagne, statut initial | `sujet`, `plateforme`, `langue`, `nb_resultats`, `statut = EN_COURS`, `execution_id`, `date_creation` (auto) |
| **C05c — Update Total Campagne** | Renseignement du volume prévu | `nb_contenus_total` |
| **C15 — Increment Traites** | Suivi d'avancement + bascule fin normale | `nb_contenus_traites` (+1), `statut = TERMINEE` (si complet), `date_fin` (si complet) |
| **E04 — Update Campagne Erreur** | Bascule fin en erreur | `statut = ERREUR`, `date_fin` |
| **C03 → C15** | Propagation de `campagne_id` dans tout le flux | — |

**Cycle de vie du statut** : `EN_COURS` → `TERMINEE` (via C15) ou `ERREUR` (via E04). Un statut terminal n'est jamais réécrit.

## Objet métier : Contenu

| Composant | Action |
|-----------|--------|
| **C04 — Collecte des contenus** | Création des contenus bruts depuis l'API YouTube |
| **C05 — Normalisation** | Mise au format du contrat de données (`contenu_source_id`, `titre`, `auteur`, `description`, `date_publication`, `plateforme`) |
| **C05a — Aggregate Contenus** | Regroupement en un unique item pour calcul du total |
| **C05b — Préparer Total Campagne** | Extraction du total et du `campagne_id` |
| **C05c — Update Total Campagne** | *(écrit sur `campagnes`, pas sur `contenus`)* |
| **C05d — Redistribuer Contenus** | Éclatement du tableau pour traitement item par item |
| **C06 — Persistance des contenus** | Insertion / mise à jour dans `contenus` (UPSERT sur `contenu_source_id`) — génère `contenu_id` |
| **C07 → C15** | Lecture / propagation (jamais de modification) |

## Objet métier : Analyse

| Composant | Action |
|-----------|--------|
| **C07 — Analyse IA** | Création de l'analyse brute par Claude Opus (`resume`, `theme`, `sentiment`, `score_qualite`, `mots_cles`, `langue`) |
| **C08 — Normalisation Analyse IA** | Validation et parsing JSON |
| **C09 — Persistance Analyse** | Enregistrement dans `analyses` (UPSERT sur `contenu_id`) — génère `analyse_id` |
| **C10 — Lecture Analyse et Contenu** | Consultation en lecture seule (JOIN contenu + analyse) |
| **C11 → C15** | Lecture / propagation |

## Objet métier : Script

| Composant | Action |
|-----------|--------|
| **C10 — Lecture Analyse et Contenu** | Consolidation contenu + analyse en objet source du script |
| **C11 — Génération Script IA** | Création du script brut par Claude Sonnet |
| **C12 — Normalisation Script IA** | Validation + réinjection des identifiants (`campagne_id`, `contenu_id`, `analyse_id`) |
| **C13 — Persistance Script** | Enregistrement dans `scripts` (UPSERT sur `analyse_id`) — génère `script_id` |
| **C14 — Préparer Increment** | Assemblage des identifiants pour le compteur |
| **C15 — Increment Traites** | *(écrit sur `campagnes`, pas sur `scripts`)* |

## Objet métier : Journal d'exécution

| Composant | Action |
|-----------|--------|
| **E01 — Capture Erreur** | Réception automatique du contexte d'erreur |
| **E02 — Structurer Erreur** | Extraction de `execution_id`, `niveau`, `etape`, `message` |
| **E03 — Log Erreur** | Insertion dans `journal_execution` avec résolution du `campagne_id` par jointure sur `execution_id` |
| **E04 — Update Campagne Erreur** | *(écrit sur `campagnes`, pas sur le journal)* |

## Vue chronologique de propagation — Workflow principal

```
C01  Recevoir Demande Campagne
        │  {sujet, plateforme, langue, nb_resultats}
        ▼
C02  Valider Paramètres
        │
        ▼
C03  Créer Campagne
        │  ➕ campagne_id, statut=EN_COURS, execution_id
        ▼
C04  Collecte des contenus
        │  contenus bruts (items YouTube)
        ▼
C05  Normalisation
        │  contenus normalisés (+ campagne_id, contenu_source_id)
        ▼
C05a Aggregate Contenus
        │  { data: [...contenus] }
        ▼
C05b Préparer Total Campagne
        │  { campagne_id, nb_total, contenus }
        ▼
C05c Update Total Campagne
        │  ➕ nb_contenus_total (sur campagnes)
        ▼
C05d Redistribuer Contenus
        │  1 item = 1 contenu
        ▼
C06  Persistance des contenus
        │  ➕ contenu_id
        ▼
C07  Analyse IA
        │  analyse brute
        ▼
C08  Normalisation Analyse IA
        │  JSON validé
        ▼
C09  Persistance Analyse
        │  ➕ analyse_id
        ▼
C10  Lecture Analyse et Contenu
        │  contenu + analyse consolidés
        ▼
C11  Génération Script IA
        │  script brut
        ▼
C12  Normalisation Script IA
        │  JSON validé + IDs réinjectés
        ▼
C13  Persistance Script
        │  ➕ script_id
        ▼
C14  Préparer Increment
        │  { script_id, campagne_id, contenu_id, analyse_id }
        ▼
C15  Increment Traites
        │  ➕ nb_contenus_traites (+1), éventuellement statut=TERMINEE + date_fin
        ▼
   Fin normale
```

## Vue chronologique de propagation — Workflow d'erreur

```
(exception dans le workflow principal)
        │
        ▼
E01  Capture Erreur (Error Trigger)
        │  contexte d'erreur brut
        ▼
E02  Structurer Erreur
        │  { execution_id, niveau, etape, message }
        ▼
E03  Log Erreur
        │  INSERT journal_execution (campagne_id résolu par jointure)
        ▼
E04  Update Campagne Erreur
        │  statut=ERREUR + date_fin (sur campagnes)
        ▼
   Fin en erreur
```

## Règles de gouvernance

Le workflow respecte les principes suivants :

1. **Unicité de création** : une donnée est créée une seule fois par un composant unique (à l'exception des colonnes de suivi de campagne, dont le partage est explicitement documenté ci-dessus).

2. **Propriété par colonne** : sur l'objet `Campagne`, chaque composant n'écrit que **les colonnes qui lui sont explicitement assignées**. Aucun composant n'écrase les colonnes d'un autre.

3. **Propagation intacte des identifiants** : `campagne_id`, `contenu_id`, `analyse_id`, `script_id`, `execution_id` sont propagés sans modification à travers le flux.

4. **Immutabilité de l'aval** : les composants en aval consultent les données produites par les composants précédents **sans jamais les altérer** (hors composants de persistance dédiés).

5. **Persistance dédiée** : les opérations de sauvegarde sont réalisées uniquement par les composants nommés `Persistance …` ou par les UPDATE explicitement documentés (C05c, C15, E04).

6. **Idempotence** : les UPSERT sur `contenu_source_id`, `contenu_id`, `analyse_id` garantissent qu'une relance ne produit jamais de doublon.

7. **Traçabilité d'incident** : toute erreur est journalisée dans `journal_execution` avec rattachement à la campagne via `execution_id`.
