### DP-V2.1-01 — Vue C minimaliste orientée action

#### Contexte
La Vue "Détail dossier" (C) contenait à l'origine tous les champs techniques du pipeline (`ambiance_visuelle`, `description_visuelle`, `parametres_recommandes`), utilisés uniquement en interne par les LLM.

#### Décision
La Vue C n'affiche **que les champs actionnables** par l'utilisateur : narration, prompt image, prompt animation, descriptions.  
Les champs pipeline restent conservés en DB mais masqués.

#### Conséquences
- UX plus claire et orientée production.
- Dette technique DT-V2.1-03 créée (champs pipeline masqués, à réévaluer en V3+).

---

### DP-V2.1-02 — Vue F : 3 dropdowns multi-outils

#### Contexte
Lors de la création d'un dossier V2, l'utilisateur doit choisir un script + un outil image + un outil animation. Un même script peut être testé avec plusieurs outils différents.

#### Décision
La Vue F propose **3 dropdowns indépendants** :
- Script
- Outil image (lu depuis `v2_outils` filtre `categorie='image' AND actif=true`)
- Outil animation (lu depuis `v2_outils` filtre `categorie='animation' AND actif=true`)

#### Conséquences
- Préserve le cas d'usage "comparer les résultats du même script avec différents outils".
- Alignement direct avec ADR-V2-04 (vérification ID ↔ catégorie).

---

### DP-V2.1-03 — Élargissement du périmètre V2.1 : intégrer aussi V1

#### Contexte
Fin S5, découverte : le dashboard permettait uniquement de **transformer** un script existant en dossier V2 (Vue F), mais **aucune interface** ne permettait de **générer** ces scripts en amont via le workflow V1 `lancer-campagne`.

**Verbatim user (fin S5)** :  
> *"On ne peut pas déployer alors qu'on ne sait pas comment déclencher la machine en backend qui produit les scripts."*

#### Décision
Élargir le périmètre V2.1 en ajoutant 2 nouvelles vues **avant tout déploiement** :
- **Vue E** : formulaire "Créer une campagne" → webhook `lancer-campagne`
- **Vue G** : liste des campagnes avec statuts + navigation vers Vue F

Plan initial 7 séances → révisé à **9 séances** (S6+S7 fusionnées en une seule séance dense).

#### Conséquences
- Le dashboard couvre désormais **le pipeline complet** (V1 → V2).
- Migration DB : `campagnes.user_id` ajouté + RLS activée + policies (résolution partielle DT-V2.1-05).
- Modifs workflow V1 `lancer-campagne` : validation + INSERT du `user_id`.

---

### DP-V2.1-04 — Plateforme YouTube uniquement en Vue E

#### Contexte
Le workflow V1 `lancer-campagne` ne collecte que YouTube (nœud `Collecte des contenus` = YouTube API uniquement).

#### Décision
Le select "plateforme" en Vue E n'affiche que `YouTube`, accompagné d'un message d'information :  
> *"TikTok et Instagram seront disponibles prochainement."*

#### Conséquences
- Alignement honnête entre le frontend et les capacités réelles du backend.
- Aucun formulaire "menteur" livré à l'utilisateur.
- Roadmap future explicite pour l'ajout de plateformes.
