# 02.V2 — Architecture Métier (V2)

## Rôle du document

Ce document décrit l'architecture **métier** de la V2 du système.
Il formalise les flux, les objets, les règles et les principes qui gouvernent le fonctionnement de la V2, indépendamment de toute considération technique.

Il répond aux questions suivantes :

- Quelles sont les grandes étapes du fonctionnement V2 ?
- Quels sont les nouveaux objets métier introduits ?
- Quelles règles métier gouvernent la V2 ?
- Comment la V2 s'articule-t-elle avec la V1 STABLE ?
- Quels sont les composants métier de la V2 ?
- Comment le catalogue d'outils est-il structuré ?

Ce document ne décrit jamais :
- les workflows n8n ;
- les tables SQL ;
- les APIs Claude ;
- le stack technique de l'interface web ;
- les choix d'implémentation.

---

## 1. Vision d'ensemble

La V2 étend fonctionnellement la V1 STABLE sans jamais la modifier.

**Principe fondateur** : la V1 apporte la matière première (le script), la V2 apporte le contexte d'exécution (tout ce qui permet de transformer ce script en vidéo prête à publier).

La V2 ne remplace donc pas la V1 : elle vient s'y greffer.

---

## 2. Positionnement V1 / V2

### 2.1 Principe d'articulation

La V2 est construite selon le principe suivant :

> **V1 STABLE reste verrouillée. V2 s'appuie sur les données produites par V1 et enrichit le processus avec de nouveaux traitements et de nouveaux objets métier, sans jamais modifier l'existant.**

### 2.2 Ce que la V2 réutilise de la V1

La V2 réutilise **intégralement** les capacités livrées par la V1 STABLE :

- la collecte de contenus depuis une plateforme ;
- l'analyse sémantique des contenus par IA ;
- la génération de scripts vidéo courts ;
- l'historisation des campagnes, contenus, analyses et scripts ;
- le suivi d'avancement et la gestion des statuts ;
- la résilience aux incidents.

### 2.3 Ce que la V2 ajoute

La V2 introduit un nouveau bloc fonctionnel qui prend le relais **une fois qu'un script V1 est disponible** :

- le choix par le créateur d'un script à produire ;
- le découpage du script en scènes ;
- la génération de prompts images optimisés pour l'outil choisi ;
- la génération de prompts animations optimisés pour l'outil choisi ;
- la génération de descriptions et hashtags par plateforme ;
- la constitution d'un dossier de production complet ;
- le suivi de l'avancement de production via une checklist ;
- la consultation de l'ensemble depuis un tableau de bord personnel.

### 2.4 Nature du lien entre V1 et V2

La V2 s'appuie sur les données produites par V1 en respectant les principes suivants :

- **Données partagées** : la V2 lit les données V1 (campagnes, contenus, analyses, scripts) sans jamais les modifier.
- **Extensions dédiées** : la V2 produit ses propres données dans de nouveaux objets métier dédiés, sans jamais empiéter sur les objets V1.
- **Réutilisation des traitements V1** : la V2 déclenche les traitements V1 existants (collecte, analyse, génération de script) sans les dupliquer.
- **Indépendance d'évolution** : la V2 peut évoluer sans impact sur la V1.

Cette approche garantit que :
- la V1 STABLE reste totalement opérationnelle et non altérée ;
- la V2 s'ajoute proprement, sans casser l'existant ;
- une V3 pourra ultérieurement suivre la même logique d'extension.

## 3. Flux métier principal

Le flux métier V2 comporte les étapes suivantes :

### Étape 1 — Ouverture du tableau de bord
Le créateur ouvre son tableau de bord personnel et visualise l'ensemble de ses campagnes en cours et passées.

### Étape 2 — Création d'une nouvelle campagne
Le créateur crée une nouvelle campagne en renseignant :
- le sujet à traiter ;
- la plateforme cible ;
- la langue ;
- **l'outil de génération d'images** qu'il souhaite utiliser (choisi dans le catalogue) ;
- **l'outil de génération d'animations** qu'il souhaite utiliser (choisi dans le catalogue).

### Étape 3 — Collecte et analyse (traitements V1 réutilisés)
Le système déclenche les traitements V1 existants :
- collecte de N contenus depuis la plateforme cible ;
- analyse sémantique de chaque contenu.

### Étape 4 — Génération des scripts candidats (traitement V1 réutilisé)
Le système déclenche la génération V1 des scripts pour chaque contenu analysé.
À l'issue de cette étape, N scripts candidats sont disponibles.

### Étape 5 — Sélection du script à produire
Le créateur consulte les N scripts candidats et sélectionne **celui qu'il souhaite transformer en vidéo**.
Ce choix relève de son expertise créative : le système ne choisit jamais à sa place.

### Étape 6 — Découpage du script en scènes
Le système découpe le script sélectionné en scènes narratives.
Chaque scène possède un numéro, un texte à dire, une ambiance visuelle et une durée estimée.

### Étape 7 — Génération des prompts images
Pour chaque scène, le système génère un prompt image optimisé pour l'**outil choisi par le créateur** au lancement de la campagne.

### Étape 8 — Génération des prompts animations
Pour chaque scène, le système génère un prompt animation optimisé pour l'**outil choisi par le créateur** au lancement de la campagne.

### Étape 9 — Génération des descriptions et hashtags
Pour chaque plateforme de publication ciblée, le système génère :
- un titre ;
- une description prête à publier ;
- une liste de hashtags optimisés.

### Étape 10 — Constitution du dossier de production
L'ensemble des livrables (script, scènes, prompts, descriptions, hashtags) est regroupé dans un **dossier de production**, accessible depuis le tableau de bord.

### Étape 11 — Production manuelle par le créateur
Le créateur exécute manuellement les étapes de production, guidé par la checklist :
- il ouvre son outil d'images et génère les visuels à partir des prompts ;
- il ouvre son outil d'animations et anime les visuels à partir des prompts ;
- il monte la vidéo dans son outil de montage (CapCut ou équivalent) ;
- il ajoute les sous-titres et effets ;
- il publie sur les plateformes cibles en utilisant les descriptions et hashtags fournis.

Chaque étape peut être cochée dans la checklist pour suivre l'avancement.

## 4. Nouveaux objets métier V2

La V2 introduit les objets métier suivants, en complément des objets V1 existants (Campagne, Contenu, Analyse, Script, Journal d'exécution).

### 4.1 Scène
Représente une unité narrative issue du découpage d'un script sélectionné.
Chaque scène est autonome et sera visualisée par une image et animée séparément.

**Rôle** : structurer la production visuelle en unités exploitables.

### 4.2 Prompt Image
Représente une instruction textuelle destinée à un outil de génération d'images.
Chaque prompt est rattaché à une scène et optimisé pour l'outil d'image choisi par le créateur.

**Rôle** : permettre au créateur de générer les visuels sans avoir à rédiger les prompts lui-même.

### 4.3 Prompt Animation
Représente une instruction textuelle destinée à un outil de génération d'animations.
Chaque prompt est rattaché à une scène et optimisé pour l'outil d'animation choisi par le créateur.

**Rôle** : permettre au créateur d'animer ses visuels sans avoir à rédiger les prompts lui-même.

### 4.4 Description de Publication
Représente le contenu prêt à publier pour une plateforme donnée : titre, description et hashtags.

**Rôle** : éviter au créateur de rédiger manuellement ses publications, tout en optimisant leur pertinence selon la plateforme.

### 4.5 Dossier de Production
Représente le regroupement de tous les livrables associés à un script sélectionné : script, scènes, prompts, descriptions, hashtags, checklist.

**Rôle** : offrir au créateur une vue unifiée et exploitable de tout ce dont il a besoin pour produire sa vidéo.

### 4.6 Checklist de Production
Représente le suivi manuel de l'avancement de production d'un dossier.
Chaque étape (génération d'images, génération d'animations, montage, publication) peut être cochée.

**Rôle** : donner au créateur une visibilité claire de son état d'avancement, sans jamais contraindre son processus.

### 4.7 Outil (élément du Catalogue)
Représente un outil externe de génération (image ou animation) référencé par le système et proposé au créateur.
Chaque outil possède un nom, une catégorie, un modèle économique, une ou plusieurs spécificités et une description.

**Rôle** : permettre au créateur de choisir un outil éclairé, sans que le système ne se substitue à sa décision.

## 5. Le Catalogue d'Outils

### 5.1 Nature du catalogue
Le catalogue d'outils est un **composant métier à part entière** de la V2.
Il constitue le référentiel officiel des outils proposés au créateur au moment de la création d'une campagne.

### 5.2 Structure du catalogue
Chaque entrée du catalogue est caractérisée par :

- **Nom** : identification claire de l'outil (ex. Midjourney, Kling AI, Ideogram).
- **Catégorie** : `image` ou `animation`.
- **Modèle économique** :
  - `gratuit` : utilisable sans paiement, sans limite significative ;
  - `freemium` : gratuit avec limites ou crédits journaliers, avec option payante ;
  - `payant` : nécessite un abonnement pour un usage effectif.
- **Spécificité** : point fort principal de l'outil (ex. mouvement humain, texte dans l'image, style cinématique).
- **Description** : courte présentation du positionnement et de l'usage recommandé.

### 5.3 Contenu minimal exigé
Le catalogue doit toujours proposer, dans chaque catégorie :

- **au moins un outil gratuit** ;
- **au moins un outil freemium** ;
- **au moins un outil payant de référence**.

Cette exigence garantit l'accessibilité de la V2 au persona ciblé (side-hustler ambitieux) tout en permettant aux créateurs disposant d'un budget de choisir des outils premium.

### 5.4 Évolutivité
Le catalogue est **vivant** : il peut être enrichi ou mis à jour pour intégrer de nouveaux outils IA à mesure que le marché évolue, sans que le fonctionnement global du système ne soit remis en question.

## 6. Règles métier V2

Les règles suivantes gouvernent le fonctionnement métier de la V2 :

### 6.1 Règles de création
- Une campagne V2 ne peut être lancée qu'à condition d'avoir :
  - un sujet renseigné ;
  - une plateforme cible ;
  - une langue ;
  - **un outil d'image choisi** dans le catalogue ;
  - **un outil d'animation choisi** dans le catalogue.

### 6.2 Règles de choix du script
- La V2 génère plusieurs scripts candidats (via la V1) mais ne produit un dossier de production **que pour un seul script sélectionné** par le créateur.
- Le créateur peut revenir en arrière et sélectionner un autre script d'une même campagne pour produire un nouveau dossier.

### 6.3 Règles sur les outils
- Un seul outil d'image et un seul outil d'animation sont utilisés pour l'ensemble d'un dossier de production (garantie de cohérence visuelle).
- Le créateur peut **relancer la génération des prompts** avec un autre outil sans repartir de la collecte ni de l'analyse.
- Le catalogue doit toujours proposer au moins un outil gratuit dans chaque catégorie.

### 6.4 Règles sur le dossier de production
- Un dossier de production est toujours rattaché à un et un seul script.
- Un dossier contient obligatoirement : script, scènes, prompts images, prompts animations, descriptions et hashtags.
- La suppression d'une campagne entraîne la suppression de l'ensemble des dossiers de production associés.

### 6.5 Règles sur la checklist
- La checklist est **purement indicative** : elle n'empêche aucune action du créateur.
- Elle permet uniquement de visualiser l'état d'avancement de la production.

### 6.6 Règles de non-modification de la V1
- La V2 ne modifie **jamais** les données produites par la V1.
- La V2 ne modifie **jamais** les workflows V1.
- La V2 ne remplace **aucune capacité** V1 : elle en étend l'usage.

## 7. Composants métier de la V2

La V2 est composée des ensembles fonctionnels suivants :

### 7.1 Composant "Création de Campagne"
- Permet au créateur de saisir les paramètres d'une nouvelle campagne, y compris le choix des outils.
- Consulte le catalogue d'outils pour proposer les choix disponibles.
- Déclenche les traitements V1 (collecte, analyse, génération de scripts).

### 7.2 Composant "Sélection de Script"
- Présente au créateur les scripts candidats issus de la V1.
- Permet la sélection d'un script à produire.

### 7.3 Composant "Découpage en Scènes"
- Analyse le script sélectionné et le découpe en scènes narratives.
- Produit les objets Scène pour la suite du traitement.

### 7.4 Composant "Générateur de Prompts Images"
- Génère, pour chaque scène, un prompt image optimisé pour l'outil d'image choisi.
- S'appuie sur les spécificités connues de chaque outil (issues du catalogue).

### 7.5 Composant "Générateur de Prompts Animations"
- Génère, pour chaque scène, un prompt animation optimisé pour l'outil d'animation choisi.
- S'appuie sur les spécificités connues de chaque outil (issues du catalogue).

### 7.6 Composant "Générateur de Descriptions et Hashtags"
- Génère les titres, descriptions et hashtags optimisés pour chaque plateforme de publication.

### 7.7 Composant "Catalogue d'Outils"
- Fournit la liste des outils disponibles, avec leurs métadonnées.
- Alimente le formulaire de création de campagne.
- Alimente les générateurs de prompts (choix des optimisations).

### 7.8 Composant "Dossier de Production"
- Regroupe l'ensemble des livrables d'un script sélectionné.
- Fournit une vue unifiée exploitable depuis le tableau de bord.

### 7.9 Composant "Checklist de Production"
- Permet au créateur de cocher les étapes de production réalisées.
- Affiche l'état d'avancement du dossier.

### 7.10 Composant "Tableau de Bord Personnel"
- Point d'entrée principal du créateur.
- Affiche l'ensemble des campagnes et dossiers de production.
- Permet la navigation entre les composants ci-dessus.

## 8. Frontières fonctionnelles

### 8.1 Ce qui est DANS la V2
- La création et le suivi de campagnes enrichies.
- La sélection du script à produire.
- Le découpage en scènes.
- La génération des prompts (images, animations).
- La génération des descriptions et hashtags.
- Le regroupement en dossier de production.
- La checklist d'avancement.
- Le tableau de bord personnel.
- Le catalogue d'outils.

### 8.2 Ce qui est HORS de la V2
- La génération réelle des images (reste manuelle, réalisée par le créateur dans son outil choisi).
- La génération réelle des animations (idem).
- Le montage vidéo (reste manuel, dans CapCut ou équivalent).
- L'ajout des sous-titres et effets.
- La publication effective sur les plateformes.
- Le suivi des performances post-publication.
- La gestion multi-utilisateurs, l'authentification, la facturation.

### 8.3 Ce qui appartient à la V1 (réutilisé sans modification)
- La collecte des contenus.
- L'analyse sémantique.
- La génération des scripts candidats.
- L'historisation des campagnes, contenus, analyses et scripts.
- Le suivi des statuts et la gestion des erreurs V1.

---

## 9. Principes d'architecture métier

La V2 respecte les principes suivants :

- **Non-régression V1** : la V1 STABLE ne doit jamais être altérée par la V2.
- **Séparation nette des responsabilités** : chaque composant a un rôle unique et clairement défini.
- **Respect de l'expertise créative** : le système propose, le créateur choisit.
- **Cohérence visuelle** : un seul outil d'image et un seul outil d'animation par campagne.
- **Accessibilité** : le catalogue doit toujours proposer des outils gratuits.
- **Guidage sans contrainte** : la checklist informe mais n'impose rien.
- **Évolutivité** : le catalogue est vivant, l'architecture peut accueillir de nouveaux composants.

---

## 10. Validation

L'architecture métier V2 est considérée comme valide lorsque :

- le flux métier principal est explicite du bout en bout ;
- tous les nouveaux objets métier introduits par la V2 sont identifiés et décrits ;
- les règles métier sont exhaustives et cohérentes ;
- le catalogue d'outils est formalisé comme un composant métier de premier ordre ;
- le positionnement V1/V2 est clair et respecte le principe de non-régression V1 ;
- les frontières fonctionnelles de la V2 sont sans ambiguïté ;
- aucune technologie d'implémentation n'apparaît dans le document.
