# 02.5 — Contrat des Données

## Rôle du document

Ce document décrit les contrats d'entrée et de sortie des composants du système.
Il répond à la question :

> **Quelles données un composant garantit-il en entrée et en sortie ?**

Il constitue le contrat officiel entre les composants.
Chaque composant peut évoluer indépendamment tant qu'il respecte ce contrat.

Ce document ne décrit jamais :
- les nœuds n8n ;
- les appels HTTP ;
- les API externes ;
- les scripts JavaScript ;
- les requêtes SQL.

---

## Granularité des contrats

Chaque contrat décrit un composant fonctionnel.
Un composant peut être implémenté par :
- plusieurs nœuds n8n ;
- un sous-workflow ;
- un microservice ;
- un script Python.

Le contrat reste indépendant de la technologie.

---

## Principe

Chaque composant possède obligatoirement :
- un **contrat d'entrée** ;
- un **contrat de sortie**.

Un composant ne peut jamais supposer l'existence d'une donnée qui ne lui est pas garantie.

**Conventions dans ce document** :
- **Nouveau** = donnée produite par le composant.
- **Propagé** = donnée transmise inchangée depuis l'amont.

---

# Partie 1 — Contrats du workflow principal

## C01 — Recevoir Demande Campagne

**Mission** : Recevoir la demande utilisateur.

**Entrée** : Aucune (point d'entrée).

**Sortie garantie** :
- Body brut de la requête, contenant potentiellement `sujet`, `plateforme`, `langue`, `nb_resultats` (non encore validés).

---

## C02 — Valider Paramètres

**Mission** : Vérifier la présence et la validité des paramètres.

**Entrée garantie** :
- Body brut issu de C01.

**Sortie garantie** :
- `sujet` (non vide)
- `plateforme` (non vide)
- `langue` (non vide)
- `nb_resultats` (entier > 0)

Le flux est interrompu si la validation échoue.

---

## C03 — Créer Campagne

**Mission** : Créer la campagne en base et générer ses identifiants.

**Entrée garantie** :
- `sujet`, `plateforme`, `langue`, `nb_resultats` (validés).

**Sortie garantie** :
- **Nouveau** : `campagne_id`, `execution_id`, `statut = EN_COURS`, `date_creation`
- **Propagé** : `sujet`, `plateforme`, `langue`, `nb_resultats`

---

## C04 — Collecte des contenus

**Mission** : Interroger la plateforme cible et récupérer les contenus.

**Entrée garantie** :
- `sujet`, `nb_resultats`, `campagne_id`.

**Sortie garantie** :
- Liste brute de contenus retournés par la plateforme (structure spécifique à la source).
- **Propagé** : `campagne_id`.

---

## C05 — Normalisation

**Mission** : Transformer les contenus bruts en objets normalisés indépendants de la plateforme.

**Entrée garantie** :
- Liste brute issue de C04.
- `campagne_id`.

**Sortie garantie** : Pour chaque contenu :
- **Nouveau** : `contenu_source_id`, `titre`, `auteur`, `description`, `date_publication`, `plateforme`
- **Propagé** : `campagne_id`

---

## C05a — Aggregate Contenus

**Mission** : Regrouper tous les contenus en un seul item pour permettre le calcul du total.

**Entrée garantie** :
- Flux d'items normalisés issus de C05.

**Sortie garantie** :
- Un item unique contenant `data` : tableau de tous les contenus normalisés.

---

## C05b — Préparer Total Campagne

**Mission** : Calculer le nombre total de contenus et extraire `campagne_id`.

**Entrée garantie** :
- Item agrégé issu de C05a.

**Sortie garantie** :
- `campagne_id`, `nb_total`, `contenus` (tableau).

---

## C05c — Update Total Campagne

**Mission** : Renseigner `nb_contenus_total` sur la campagne.

**Entrée garantie** :
- `campagne_id`, `nb_total`.

**Sortie garantie** :
- Confirmation que `campagnes.nb_contenus_total` est mis à jour.

---

## C05d — Redistribuer Contenus

**Mission** : Éclater le tableau agrégé en items individuels.

**Entrée garantie** :
- Objet consolidé produit par C05b.

**Sortie garantie** :
- Flux d'items : un contenu normalisé par item, avec tous les champs de la sortie de C05.

---

## C06 — Persistance des contenus

**Mission** : Enregistrer chaque contenu en base de manière idempotente.

**Entrée garantie** :
- Un contenu normalisé (issu de C05d).

**Sortie garantie** :
- **Nouveau** : `contenu_id` (identifiant persistant)
- **Propagé** : tous les champs du contenu + `campagne_id`

---

## C07 — Analyse IA

**Mission** : Produire une analyse sémantique structurée du contenu.

**Entrée garantie** :
- `contenu_id`, `titre`, `description`, `plateforme`.

**Sortie garantie** :
- Réponse brute du modèle, contenant une structure JSON avec : `contenu_id`, `resume`, `theme`, `sentiment`, `score_qualite`, `mots_cles`, `langue`.

---

## C08 — Normalisation Analyse IA

**Mission** : Valider et nettoyer la réponse du modèle.

**Entrée garantie** :
- Réponse brute issue de C07.

**Sortie garantie** :
- Objet JSON validé et conforme, contenant obligatoirement :
  - `contenu_id`
  - `resume`
  - `theme`
  - `sentiment` (`Positif` | `Neutre` | `Négatif`)
  - `score_qualite` (entier 0–100)
  - `mots_cles` (tableau)
  - `langue`

---

## C09 — Persistance Analyse

**Mission** : Enregistrer l'analyse en base et générer `analyse_id`.

**Entrée garantie** :
- Objet d'analyse normalisé.

**Sortie garantie** :
- **Nouveau** : `analyse_id`
- **Propagé** : `contenu_id`, tous les champs de l'analyse.

---

## C10 — Lecture Analyse et Contenu

**Mission** : Fournir un objet consolidé prêt pour la génération de script.

**Entrée garantie** :
- `analyse_id`.

**Sortie garantie** :
- Objet consolidé contenant :
  - `analyse_id`, `contenu_id`, `campagne_id`
  - `titre`, `auteur`, `description`, `date_publication`, `plateforme`
  - `resume`, `theme`, `sentiment`, `score_qualite`, `mots_cles`, `langue`

---

## C11 — Génération Script IA

**Mission** : Produire un script vidéo à partir du couple contenu + analyse.

**Entrée garantie** :
- Objet consolidé issu de C10.

**Sortie garantie** :
- Réponse brute du modèle contenant une structure JSON avec `script`.

---

## C12 — Normalisation Script IA

**Mission** : Extraire le script et réinjecter les identifiants relationnels.

**Entrée garantie** :
- Réponse brute issue de C11.
- Contexte consolidé issu de C10.

**Sortie garantie** :
- `campagne_id`, `contenu_id`, `analyse_id`, `script`.

---

## C13 — Persistance Script

**Mission** : Enregistrer le script en base et générer `script_id`.

**Entrée garantie** :
- Objet script normalisé (sortie de C12).

**Sortie garantie** :
- **Nouveau** : `script_id`
- **Propagé** : `campagne_id`, `contenu_id`, `analyse_id`, `script`.

---

## C14 — Préparer Increment

**Mission** : Assembler les identifiants nécessaires à l'incrément du compteur.

**Entrée garantie** :
- Objet script persisté (sortie de C13).
- Objet script normalisé (contexte de C12).

**Sortie garantie** :
- `script_id`, `campagne_id`, `contenu_id`, `analyse_id`.

---

## C15 — Increment Traites

**Mission** : Mettre à jour le compteur de la campagne et détecter la fin normale.

**Entrée garantie** :
- `campagne_id`.

**Sortie garantie** :
- `campagnes.nb_contenus_traites` est incrémenté de +1.
- Si `nb_contenus_traites` atteint `nb_contenus_total` → `statut = TERMINEE` + `date_fin` renseignée.
- Sinon, `statut` et `date_fin` restent inchangés.

---

# Partie 2 — Contrats du workflow d'erreur

## E01 — Capture Erreur

**Mission** : Recevoir automatiquement le contexte d'erreur du workflow principal.

**Entrée garantie** :
- Contexte d'erreur fourni par le moteur d'orchestration (`execution.id`, `execution.error`, `lastNodeExecuted`).

**Sortie garantie** :
- Objet brut contenant le contexte d'exécution en erreur.

---

## E02 — Structurer Erreur

**Mission** : Extraire les informations utiles du contexte d'erreur.

**Entrée garantie** :
- Contexte brut issu de E01.

**Sortie garantie** :
- `execution_id`
- `niveau` (ex : `ERREUR`)
- `etape` (nom du composant ayant échoué)
- `message` (description exploitable)

---

## E03 — Log Erreur

**Mission** : Enregistrer l'erreur dans le journal, rattachée à la campagne.

**Entrée garantie** :
- `execution_id`, `niveau`, `etape`, `message` (sortie de E02).

**Sortie garantie** :
- Une entrée est créée dans `journal_execution` avec :
  - `campagne_id` (résolu par correspondance sur `execution_id`)
  - `niveau`, `etape`, `message`, `date_evenement`.

---

## E04 — Update Campagne Erreur

**Mission** : Marquer la campagne comme terminée en erreur.

**Entrée garantie** :
- `execution_id`.

**Sortie garantie** :
- La campagne correspondante voit son `statut` passer à `ERREUR` et `date_fin` renseignée.

---

# Partie 3 — Contrats prévus pour les versions ultérieures

## Publication / Tableau de bord *(V2)*

**Entrée prévue** : `campagne_id`, contenus, analyses, scripts consolidés.
**Sortie prévue** : Publication consolidée disponible via API ou interface.

## Enrichissement métriques d'engagement *(V2)*

**Entrée prévue** : `contenu_source_id`, `plateforme`.
**Sortie prévue** : `nombre_vues`, `nombre_likes`, `nombre_commentaires`, `hashtags`, `url` — non collectés en V1.

## Notification externe *(V2)*

**Entrée prévue** : `campagne_id`, statut final.
**Sortie prévue** : Notification envoyée (email, webhook, …).

---

## Règles de gouvernance

Un composant :
1. **ne dépend jamais** d'un composant situé plus loin dans le workflow ;
2. **ne modifie jamais** une donnée dont il n'est pas responsable ;
3. **ajoute uniquement** les données relevant de sa mission (champs "Nouveau") ;
4. **propage sans altération** les identifiants et champs reçus (champs "Propagé") ;
5. **garantit toujours** les données annoncées dans son contrat de sortie ;
6. **ne supprime jamais** une donnée produite par un composant précédent ;
7. **respecte la propriété par colonne** sur l'objet Campagne : seul C03 crée, seul C05c écrit `nb_contenus_total`, seul C15 écrit `nb_contenus_traites`, seul E04 écrit `statut = ERREUR`.

En cas de conflit entre ce document et l'implémentation réelle, **ce contrat prévaut** : l'implémentation doit être corrigée.
