## 1. Objectif du document

Ce document décrit l'architecture complète des workflows V2 du projet
Créateur de Contenu IA. Il formalise :

- la séquence et le rôle de chaque nœud de traitement V2 ;
- les points de lecture sur les données V1 (frontière V1/V2) ;
- la réutilisation des workflows V1 sans modification ;
- la politique de gestion des erreurs, isolée par générateur ;
- la traçabilité complète entre chaque exécution et les données produites.

Ce document est un document d'architecture métier. Il ne décrit pas
l'implémentation technique des nœuds, mais le comportement attendu
de chaque étape et les responsabilités de chaque workflow.

---

## 2. Principes structurants

### 2.1 Architecture E3-a — Base partagée, écriture isolée

V2 s'appuie sur le principe d'architecture E3-a acté en V2-002 :

- **V1 et V2 partagent la même base de données.**
- **V2 lit les données V1 en lecture seule.** Elle ne modifie jamais
  les tables V1 (`campagnes`, `contenus`, `analyses`, `scripts`,
  `journal_execution`).
- **V2 écrit exclusivement dans ses propres tables** (préfixe `v2_`).
- La frontière entre V1 et V2 est matérialisée par un nœud de lecture
  unique et explicite : **C-V2-03 · Lire Contexte V1**.

### 2.2 Modularité par responsabilité

Les workflows V2 sont organisés par responsabilité fonctionnelle,
et non par outil ou par étape technique. Chaque workflow est autonome,
testable et remplaçable indépendamment des autres.

Cinq workflows composent l'architecture V2 :

| Identifiant workflow | Nom fonctionnel | Responsabilité |
|---|---|---|
| V2-ORCH | Orchestrateur V2 | Entrée, validation, lecture V1, initialisation campagne V2 |
| V2-SCENE | Générateur de Scènes | Découpage du script en scènes structurées |
| V2-PLAN | Générateur de Plans | Découpage de chaque scène en plans visuels |
| V2-IMG | Générateur de Prompts Image | Production du prompt image par plan |
| V2-ANIM | Générateur de Prompts Animation | Production du prompt animation par plan |
| V2-ERR | Gestionnaire d'Erreurs V2 | Capture, journalisation et isolation des erreurs |

### 2.3 Résilience isolée par générateur

Contrairement à V1 où une erreur met l'intégralité de la campagne
en statut `ERREUR`, V2 applique une politique de résilience isolée :

- Une erreur sur un plan n'interrompt pas le traitement des autres plans.
- Le plan en échec est marqué individuellement avec le statut `ERREUR`
  dans `v2_plans`.
- La campagne V2 continue son exécution et se clôture normalement,
  en indiquant le nombre de plans traités avec succès et le nombre
  de plans en erreur.
- Chaque erreur est journalisée dans `v2_journal_execution` avec
  l'identifiant précis du plan concerné.

### 2.4 Séquentialité des générateurs par plan

Pour chaque plan, la génération du prompt image précède la génération
du prompt animation. Ces deux opérations sont séquentielles.

Ce choix garantit :
- la robustesse de l'orchestration (pas de synchronisation parallèle) ;
- la simplicité du diagnostic en cas d'erreur sur un plan donné ;
- la cohérence des données persistées (prompt image disponible avant
  que le prompt animation soit produit).

### 2.5 Convention de nommage des nœuds

Tous les nœuds V2 suivent la convention `C-V2-XX`, où `XX` est un
numéro séquentiel propre à chaque workflow, repartant à 01.

Les nœuds du workflow de gestion des erreurs suivent la convention
`E-V2-XX`, en miroir de la convention `E01–E04` du workflow d'erreur V1.

## 3. Cartographie V1 — Ce que V2 consomme

### 3.1 Rappel du comportement V1

Le workflow V1 produit, pour chaque campagne lancée, les données
suivantes dans la base partagée :

| Table V1 | Contenu | Clé de matching |
|---|---|---|
| `campagnes` | Paramètres de la campagne, statut, compteurs | `id`, `execution_id` |
| `contenus` | Vidéos collectées depuis YouTube | `contenu_source_id` |
| `analyses` | Analyse IA de chaque contenu (résumé, thème, sentiment, score, mots-clés) | `contenu_id` |
| `scripts` | Script vidéo généré par contenu analysé | `analyse_id`, `contenu_id` |
| `journal_execution` | Journal des erreurs V1 | `campagne_id` |

V1 génère **un script par contenu collecté**. Pour une campagne
de 10 résultats YouTube, 10 scripts sont disponibles en base
à la fin de l'exécution V1.

V1 signale la fin de son exécution en passant la campagne
au statut `TERMINEE`.

### 3.2 Point de frontière V1/V2

V2 ne démarre que si les conditions suivantes sont réunies :

1. Le script ciblé existe dans la table `scripts` (identifié par `script_id`).
2. La campagne V1 associée est en statut `TERMINEE`.
3. Les outils choisis par le créateur (outil image + outil animation)
   sont présents dans le catalogue V2.

Ces trois vérifications sont effectuées dans le nœud
**C-V2-02 · Valider Paramètres V2**, avant toute écriture en base.

### 3.3 Lecture unique du contexte V1

L'ensemble des données V1 nécessaires à V2 est lu en une seule
opération dans le nœud **C-V2-03 · Lire Contexte V1**.

Cette lecture effectue une jointure sur trois tables V1 :
scripts
└── JOIN analyses (via analyses.contenu_id = scripts.contenu_id)
└── JOIN contenus (via contenus.id = scripts.contenu_id)
WHERE scripts.id = [script_id entrant]

text


Les données extraites alimentent l'intégralité de la chaîne V2 :
le script complet, l'analyse associée (thème, mots-clés, sentiment,
score qualité), et les métadonnées du contenu source (titre, auteur,
plateforme).

**Ce nœud est le seul point de contact entre V2 et les données V1.**
Toute évolution de la structure V1 n'impacte que ce nœud.

## 4. Workflow V2-ORCH — Orchestrateur V2

**Responsabilité** : Recevoir la demande du créateur, valider les
paramètres, lire le contexte V1, initialiser la campagne V2,
et transmettre le contexte enrichi aux workflows suivants.

### Séquence des nœuds

| Nœud | Nom fonctionnel | Action |
|---|---|---|
| C-V2-01 | Recevoir Demande V2 | Webhook POST. Reçoit : `script_id`, `outil_image`, `outil_animation`. |
| C-V2-02 | Valider Paramètres V2 | Vérifie : `script_id` non vide, `outil_image` dans le catalogue, `outil_animation` dans le catalogue, campagne V1 associée en statut `TERMINEE`. |
| C-V2-03 | Lire Contexte V1 | SELECT avec JOIN sur `scripts`, `analyses`, `contenus`. Lecture seule. Extrait : script complet, thème, mots-clés, sentiment, score qualité, titre, auteur, plateforme. |
| C-V2-04 | Créer Campagne V2 | INSERT dans `v2_campagnes`. Statut initial : `EN_COURS`. Enregistre `script_id`, `outil_image`, `outil_animation`, `execution_id`. |

### Données produites

À l'issue de V2-ORCH, le contexte transmis aux workflows suivants
contient :

- `v2_campagne_id` : identifiant de la campagne V2 créée
- `script` : texte complet du script V1 choisi
- `script_id` : identifiant du script V1 source
- `theme`, `mots_cles`, `sentiment`, `score_qualite` : données d'analyse V1
- `outil_image`, `outil_animation` : outils choisis par le créateur
- `execution_id` : identifiant d'exécution V2 pour la traçabilité

### Comportement en cas d'erreur

Si la validation échoue (C-V2-02), le workflow s'arrête sans écriture
en base. Un message d'erreur explicite est retourné au demandeur
(script inexistant, campagne V1 non terminée, outil non reconnu).

Si C-V2-03 ou C-V2-04 échoue, le workflow V2-ERR est déclenché.

## 5. Workflow V2-SCENE — Générateur de Scènes

**Responsabilité** : Découper le script V1 choisi en scènes
structurées et les persister dans `v2_scenes`.

### Séquence des nœuds

| Nœud | Nom fonctionnel | Action |
|---|---|---|
| C-V2-05 | Générer Scènes IA | Soumet le script complet à l'IA. Consigne : découper en scènes narratives cohérentes. Chaque scène reçoit un numéro d'ordre, un titre et une description. Retourne un JSON structuré. |
| C-V2-06 | Normaliser Scènes | Parse le JSON IA. Nettoie les balises éventuelles. Valide la présence des champs obligatoires (numero_ordre, titre, description). |
| C-V2-07 | Persister Scènes | INSERT dans `v2_scenes` pour chaque scène. Associe `v2_campagne_id`. |
| C-V2-08 | Redistribuer Scènes | Éclate le tableau de scènes en items individuels. Chaque item porte : `v2_scene_id`, `v2_campagne_id`, `outil_image`, `outil_animation`, `description_scene`. |

### Données produites

- Table `v2_scenes` alimentée : une ligne par scène
- Contexte transmis au workflow suivant : `v2_scene_id` + description
  de la scène + outils choisis

### Comportement en cas d'erreur

Une erreur sur C-V2-05 ou C-V2-06 (génération ou parsing) déclenche
V2-ERR. La campagne V2 est marquée `ERREUR` si aucune scène n'a pu
être produite (échec total). Si une partie des scènes est produite,
le traitement continue sur les scènes disponibles.

---

## 6. Workflow V2-PLAN — Générateur de Plans

**Responsabilité** : Découper chaque scène en plans visuels distincts
et les persister dans `v2_plans`.

Ce workflow reçoit un item par scène (issu de C-V2-08) et traite
chaque scène de façon indépendante.

### Séquence des nœuds

| Nœud | Nom fonctionnel | Action |
|---|---|---|
| C-V2-09 | Générer Plans IA | Soumet la description de la scène à l'IA. Consigne : découper en plans visuels. Chaque plan reçoit un numéro d'ordre, une description visuelle, une durée estimée et un cadrage suggéré. Retourne un JSON structuré. |
| C-V2-10 | Normaliser Plans | Parse le JSON IA. Valide les champs obligatoires (numero_ordre, description_visuelle). |
| C-V2-11 | Persister Plans | INSERT dans `v2_plans` pour chaque plan. Associe `v2_scene_id` et `v2_campagne_id`. Statut initial : `EN_ATTENTE`. |
| C-V2-12 | Redistribuer Plans | Éclate le tableau de plans en items individuels. Chaque item porte : `v2_plan_id`, `v2_scene_id`, `v2_campagne_id`, `description_visuelle`, `outil_image`, `outil_animation`. |

### Données produites

- Table `v2_plans` alimentée : une ligne par plan
- Contexte transmis aux workflows suivants : `v2_plan_id` + description
  visuelle + outils choisis

### Comportement en cas d'erreur

Une erreur sur un plan donné n'interrompt pas les autres plans.
Le plan en échec est marqué `ERREUR` dans `v2_plans`.
L'erreur est journalisée dans `v2_journal_execution` avec le `v2_plan_id`
concerné. Les plans restants continuent leur traitement.

---

## 7. Workflow V2-IMG — Générateur de Prompts Image

**Responsabilité** : Produire, pour chaque plan, un prompt image
adapté à l'outil image choisi par le créateur, et le persister
dans `v2_prompts_image`.

Ce workflow reçoit un item par plan (issu de C-V2-12).

### Séquence des nœuds

| Nœud | Nom fonctionnel | Action |
|---|---|---|
| C-V2-13 | Générer Prompt Image IA | Soumet la description visuelle du plan à l'IA, en précisant l'outil image cible. Consigne : produire un prompt optimisé pour les conventions de l'outil (style, ratio, qualificatifs). Retourne un JSON structuré. |
| C-V2-14 | Normaliser Prompt Image | Parse le JSON IA. Valide la présence du champ `prompt_image`. |
| C-V2-15 | Persister Prompt Image | INSERT dans `v2_prompts_image`. Associe `v2_plan_id`, `outil_utilise`, `prompt_genere`. Met à jour le statut du plan : `PROMPT_IMAGE_OK`. |

### Données produites

- Table `v2_prompts_image` alimentée : une ligne par plan
- Statut du plan mis à jour dans `v2_plans`
- Contexte transmis au workflow suivant : `v2_plan_id`, `v2_campagne_id`,
  `outil_animation`

### Comportement en cas d'erreur

Une erreur sur ce workflow pour un plan donné déclenche V2-ERR.
Le plan est marqué `ERREUR` dans `v2_plans`. Le workflow V2-ANIM
ne se déclenche pas pour ce plan (la séquence est interrompue
au niveau du plan en échec, pas au niveau de la campagne).

---

## 8. Workflow V2-ANIM — Générateur de Prompts Animation

**Responsabilité** : Produire, pour chaque plan ayant un prompt image
valide, un prompt animation adapté à l'outil animation choisi, et le
persister dans `v2_prompts_animation`.

Ce workflow reçoit un item par plan (issu de C-V2-15), uniquement
si le prompt image a été produit avec succès.

### Séquence des nœuds

| Nœud | Nom fonctionnel | Action |
|---|---|---|
| C-V2-16 | Générer Prompt Animation IA | Soumet la description visuelle du plan et le prompt image produit à l'IA, en précisant l'outil animation cible. Consigne : produire un prompt animation cohérent avec l'image, optimisé pour les conventions de l'outil (mouvement, durée, style cinématique). Retourne un JSON structuré. |
| C-V2-17 | Normaliser Prompt Animation | Parse le JSON IA. Valide la présence du champ `prompt_animation`. |
| C-V2-18 | Persister Prompt Animation | INSERT dans `v2_prompts_animation`. Associe `v2_plan_id`, `outil_utilise`, `prompt_genere`. Met à jour le statut du plan : `COMPLET`. |
| C-V2-19 | Incrémenter Plans Traités | UPDATE `v2_campagnes` : `nb_plans_traites += 1`. Si `nb_plans_traites >= nb_plans_total` : statut = `TERMINEE`, `date_fin = NOW()`. |

### Données produites

- Table `v2_prompts_animation` alimentée : une ligne par plan
- Statut du plan mis à jour dans `v2_plans` : `COMPLET`
- Compteur de la campagne V2 mis à jour dans `v2_campagnes`

### Comportement en cas d'erreur

Une erreur sur ce workflow pour un plan donné déclenche V2-ERR.
Le plan est marqué `ERREUR`. Le compteur `nb_plans_traites` est
tout de même incrémenté (le plan a été traité, même en échec),
afin que la campagne puisse se clôturer correctement.

---

## 9. Workflow V2-ERR — Gestionnaire d'Erreurs V2

**Responsabilité** : Capturer toute erreur survenant dans les
workflows V2, la journaliser dans `v2_journal_execution`, et
marquer le plan concerné en erreur dans `v2_plans`.

Ce workflow est le miroir fonctionnel du workflow d'erreur V1
(`E01–E04`), adapté à la politique de résilience isolée V2.

### Séquence des nœuds

| Nœud | Nom fonctionnel | Action |
|---|---|---|
| E-V2-01 | Capturer Erreur V2 | Déclenchement sur erreur de tout workflow V2. Récupère : `execution_id`, nom du nœud en échec, message d'erreur. |
| E-V2-02 | Structurer Erreur V2 | Produit un objet structuré : `execution_id`, `niveau = ERREUR`, `etape` (nom du nœud), `message`, `v2_plan_id` si disponible. |
| E-V2-03 | Journaliser Erreur V2 | INSERT dans `v2_journal_execution`. Associe `v2_campagne_id` via jointure sur `v2_campagnes.execution_id`. |
| E-V2-04 | Marquer Plan En Erreur | UPDATE `v2_plans` SET `statut = ERREUR` WHERE `id = v2_plan_id`. N'affecte que le plan concerné. La campagne V2 reste en cours. |

### Différence fondamentale avec V1

| Comportement | V1 | V2 |
|---|---|---|
| Périmètre de l'erreur | Toute la campagne passe en `ERREUR` | Seul le plan concerné passe en `ERREUR` |
| Poursuite du traitement | Le workflow s'arrête | Les autres plans continuent |
| Table mise à jour | `campagnes` | `v2_plans` |
| Journal | `journal_execution` | `v2_journal_execution` |

## 11. Traçabilité exécution ↔ données produites

Chaque exécution V2 est traçable de bout en bout grâce aux
chaînes de clés étrangères suivantes :
v2_campagnes.execution_id ← identifiant d'exécution n8n
└── v2_campagnes.script_id ← lien vers public.scripts (V1)
└── v2_scenes.v2_campagne_id
└── v2_plans.v2_scene_id
└── v2_prompts_image.v2_plan_id
└── v2_prompts_animation.v2_plan_id
v2_journal_execution.v2_campagne_id ← journal d'erreurs V2

text


Pour tout incident, il est possible de retrouver :
- quelle campagne V2 était en cours ;
- quel script V1 avait été sélectionné ;
- quelle scène, quel plan, quel générateur a produit l'erreur ;
- l'état exact des données au moment de l'erreur.

## 12. Règles de non-régression V1

Les règles suivantes sont impératives et ne souffrent d'aucune
exception dans V2 :

| Règle | Description |
|---|---|
| R-NR-01 | V2 ne réalise aucune opération d'écriture sur les tables V1. |
| R-NR-02 | V2 ne modifie jamais le statut d'une campagne V1. |
| R-NR-03 | V2 ne modifie jamais les scripts, analyses ou contenus V1. |
| R-NR-04 | Le nœud C-V2-03 est le seul point de lecture V1 autorisé. |
| R-NR-05 | Toute évolution de la structure V1 ne doit impacter que C-V2-03. |

---

## 13. Évolutions anticipées (hors périmètre V2)

Les points suivants sont identifiés comme évolutions naturelles
pour une version V3, sans impact sur l'architecture V2 actuelle :

- **Parallélisation** des workflows V2-IMG et V2-ANIM par plan,
  pour réduire le temps de traitement sur les campagnes à grand
  nombre de plans.
- **Workflow adaptateur V1/V2** dédié, isolant complètement
  la lecture V1 dans un composant réutilisable.
- **Déclenchement automatique V2** sur nouvelle campagne V1
  terminée, via un trigger base de données.
- **Support multi-scripts** : sélection et traitement de plusieurs
  scripts V1 au sein d'une même campagne V2.
