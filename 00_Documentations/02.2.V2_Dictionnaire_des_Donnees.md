# 02.2.V2 — Dictionnaire des Données (V2)

## Rôle du document

Ce document définit de manière précise toutes les données introduites par la V2.
Il constitue la **référence officielle** pour comprendre la signification des attributs de chaque objet métier V2.

Il répond aux questions suivantes :

- Quelles données composent chaque nouvel objet métier V2 ?
- Que signifie chaque donnée ?
- Quel est son rôle dans le système ?
- Est-elle obligatoire ou facultative ?
- Quelle est l'origine de cette donnée (utilisateur, système, IA, catalogue) ?
- Quelles sont les valeurs possibles pour les données à choix contraint ?

Ce document ne décrit jamais :
- les tables SQL ;
- les types de données techniques ;
- les workflows ;
- les APIs ;
- les technologies utilisées.

---

## 1. Positionnement par rapport à la V1

Ce dictionnaire complète celui de la V1 (`02.2_Dictionnaire_des_Donnees.md`) sans le modifier.
Les objets V1 (Campagne, Contenu, Analyse, Script, Journal d'exécution) restent définis dans le dictionnaire V1 et sont réutilisés tels quels par la V2.

Seuls les **nouveaux objets métier V2** sont documentés ici :
- Dossier de Production
- Scène
- Plan
- Prompt Image
- Prompt Animation
- Description de Publication
- Outil (élément du Catalogue)
- Checklist de Production
- Étape de Checklist

## Objet : Dossier de Production

| Donnée | Description | Obligatoire | Origine | Remarques |
|--------|-------------|-------------|---------|-----------|
| `dossier_id` | Identifiant unique du dossier de production | Oui | Système | Généré automatiquement à la création |

| `date_creation` | Date de création du dossier | Oui | Système | Générée automatiquement |
| `date_derniere_modification` | Date de la dernière action sur le dossier | Oui | Système | Mise à jour à chaque modification (ex. checklist cochée) |

## Règles générales

- Chaque objet possède un identifiant unique.
- Une donnée appartient à un seul objet métier.
- Une donnée possède une signification unique dans tout le système V2.
- Les données générées par l'IA sont conservées afin de garantir la traçabilité des traitements.
- Les données saisies par le créateur (choix d'outil, choix de script, checklist cochée) sont conservées telles quelles.
- Les relations entre les objets sont assurées par leurs identifiants métier.
- L'origine de chaque donnée (utilisateur, système, IA, catalogue) est explicite.
- Les données V1 (Campagne, Script, etc.) ne sont pas redéfinies ici et sont réutilisées telles que définies dans `02.2_Dictionnaire_des_Donnees.md`.

---

## Règles spécifiques V2

- Un dossier de production est toujours rattaché à une **campagne V1 existante** et à un **script V1 existant**.
- Les outils choisis (`outil_image_id` et `outil_animation_id`) doivent obligatoirement exister dans le catalogue et être marqués comme `actif`.
- La somme des `duree_estimee` des plans d'une scène doit correspondre à la `duree_estimee` de la scène.
- Un prompt (image ou animation) conserve la trace de l'outil pour lequel il a été généré (`outil_id`), même si l'outil du dossier change ultérieurement.
- Le statut d'un dossier passe manuellement de `EN_COURS` à `TERMINE` lorsque le créateur considère la production comme achevée.
- La checklist est créée automatiquement à la création du dossier, avec un jeu d'étapes standard adapté au dossier.
- Une étape cochée renseigne automatiquement `date_realisation`.

## Validation

Le dictionnaire V2 est considéré comme valide lorsque :

- toutes les données du modèle conceptuel V2 (`02.1.V2`) sont documentées ;
- chaque donnée possède une définition claire et non ambiguë ;
- l'origine de chaque donnée est identifiée ;
- les valeurs possibles des données à choix contraint sont explicites (statuts, catégories, modèles économiques) ;
- les règles métier associées sont documentées ;
- les relations avec les objets V1 sont respectées et explicites ;
- aucune technologie d'implémentation n'apparaît dans ce document.
